## מה מטרת הפרויקט?

הפרויקט אוסף מודעות מכירה של דירות ובתים מארגנטינה ומאורוגוואי, בודק את
איכות הנתונים, מנתח קשרים בין מאפייני הנכס למחיר ובונה מודל בסיסי להערכת
מחיר מודעה בדולרים.

המודל מעריך מחיר של מודעה הדומה למודעות שנאספו. הוא לא חוזה כיצד מחירי
השוק ישתנו בעתיד, מפני שהנתונים הם תמונת מצב אחת ולא סדרת נתונים היסטורית.
ההצעה המקורית כללה גם שכירות, שילוב ישיר של משתנים מאקרו־כלכליים וחיזוי
עתידי. המימוש הסופי מתמקד במודעות מכירה, משתמש במאקרו כהקשר בלבד ומעריך
מחיר מודעה נוכחי. יש להציג את התאמת ההיקף הזאת למרצה ולקבל את אישורו.

## מה יש בכל תיקייה?

### `code` — הקוד והמחברות

- `scrape_real_estate_training_data.py` — אוסף מודעות מהאתרים המורשים, מנקה
  שדות, מסיר כפילויות וכותב את קובצי הנתונים.
- `fetch_macroeconomic_data.py` — מוריד מה־World Bank נתוני אינפלציה וצמיחת
  תמ״ג עבור ארגנטינה ואורוגוואי.
- `eda_real_estate.ipynb` — בודק איכות נתונים, התפלגות מחירים, חריגים,
  אזורים וקורלציות. המחברת מיועדת לניתוח בלבד ואינה מאמנת מודל.
- `real_estate_model.ipynb` — המקור הראשי של המודל: בחירת מאפיינים, חלוקת
  הנתונים, preprocessing, השוואת מודלים, מדדי בדיקה וגרפים.
- `predict_property.py` — ממשק בסיסי בטרמינל. הוא מבקש באנגלית את פרטי הנכס,
  מאמן את אותו מודל Ridge על קובץ הנתונים העדכני ומציג הערכת מחיר בדולר. לא
  נשמר קובץ מודל בינארי נוסף.

### `data` — הנתונים

- `scraped_real_estate_training.csv` — הנתונים המלאים לאחר ניקוי: 1,777

## האם יש חלוקה לאימון ולבדיקה?

כן. החלוקה מוגדרת ב־`real_estate_model.ipynb` עם `random_state=42`, ולכן היא
ניתנת לשחזור:

| חלק | אחוז | מספר רשומות | שימוש |
| --- | ---: | ---: | --- |
| אימון | 80% | 1,351 | אימון, preprocessing ובחירת המודל |
| בדיקה סופית | 20% | 338 | הערכה אחת של המודל שנבחר |

בתוך 1,351 רשומות האימון מתבצעת גם בדיקת 5-fold cross-validation. בכל סבב
המודל מתאמן על ארבעה חלקים ונבדק על החלק החמישי. כך בחירת המודל נעשית בלי
להסתכל על קבוצת הבדיקה הסופית.

גם השלמת ערכים חסרים, scaling ו־one-hot encoding נמצאים בתוך pipeline
שמותאם רק לנתוני האימון בכל fold. הדבר מונע זליגת מידע מקבוצת הבדיקה.
העמודה `price_per_sqm` אינה משמשת כמאפיין, מפני שהיא מחושבת מהמחיר שאותו
מנסים לחזות והייתה יוצרת זליגת יעד.

## תוצאות המודל

המודל שנבחר על נתוני האימון הוא Ridge Regression.

### תוצאות cross-validation על נתוני האימון

| מדד | תוצאה |
| --- | ---: |
| R² ממוצע | 0.628 |
| סטיית תקן של R² בין ה־folds | 0.159 |
| MAE ממוצע | 107,995 דולר |

### תוצאות על קבוצת הבדיקה שלא שימשה לבחירת המודל

| מדד | תוצאה | פירוש פשוט |
| --- | ---: | --- |
| R² | 0.475 | המודל מסביר כ־47.5% מהשונות במחירי קבוצת הבדיקה |
| MAE | 105,473 דולר | טעות מוחלטת ממוצעת של כ־105 אלף דולר למודעה |
| RMSE | 307,037 דולר | מדד שמעניש במיוחד טעויות גדולות וחריגים |
| MAPE | 27.2% | התחזית רחוקה בממוצע בכ־27.2% מהמחיר בפועל |

זהו מודל רגרסיה, ולכן אין לו "אחוז דיוק" כמו במודל סיווג. לא נכון להציג
`100% - MAPE` כ־72.8% דיוק. המדדים הנכונים להצגה הם R², MAE, RMSE ו־MAPE.

### תוצאות לפי קבוצה בקבוצת הבדיקה

| קבוצה | רשומות | R² | MAE | MAPE |
| --- | ---: | ---: | ---: | ---: |
| ארגנטינה | 110 | 0.684 | 84,985 דולר | 31.8% |
| אורוגוואי | 228 | 0.442 | 115,358 דולר | 25.0% |
| דירות | 258 | 0.522 | 74,156 דולר | 21.0% |
| בתים | 80 | 0.168 | 206,470 דולר | 47.0% |

הטבלה מראה שהמודל אמין יותר לדירות מאשר לבתים. לכן חיזוי לבית מוצג עם
אזהרה בכלי הטרמינל ויש להתייחס אליו כאומדן גס יותר.

## האם המודל עובד כמו שצריך?

כן, מבחינה טכנית ומתודולוגית בסיסית:

- שתי המחברות הורצו מחדש מתחילתן ועד סופן ללא שגיאת הרצה.
- התקבלו אותם מדדי בדיקה שמופיעים כעת במחברת וב־README.
- אין בקובץ המודל שורות כפולות זהות, מחירי יעד חסרים או מחירים לא חיוביים.
- המודל משתמש ב־1,689 רשומות, 38 מאפיינים מספריים ו־10 מאפיינים קטגוריאליים
  זמינים. מאפיינים שכל הערכים בהם חסרים אינם נכנסים בפועל למודל.
- קבוצת הבדיקה נשמרת מחוץ לתהליך בחירת המודל.
- preprocessing ובחירת המודל מתבצעים על נתוני האימון בלבד.
- אין שימוש ב־`price_per_sqm` או בעמודת מחיר נוספת כמאפיין.

עם זאת, זהו baseline שצריך להציג עם הסתייגויות. סטיית התקן של R² ב־CV היא
0.159, ולכן הביצועים משתנים בין חלוקות. בנוסף, 1,110 מתוך 1,689 הרשומות הן
מאורוגוואי, 1,261 הן דירות, ובנתונים המלאים 1,185 מתוך 1,777 הרשומות הגיעו
מ־InfoCasas. לכן המודל מתאים יותר למודעות הדומות למדגם מאשר לכל שוק הנדל״ן
בארגנטינה ובאורוגוואי.

האיסוף הממוקד הגדיל במיוחד את מספר הבתים מארגנטינה, אבל המדד הכולל לא
השתפר: קבוצת הבדיקה החדשה רחבה וקשה יותר. זה ממחיש שכמות גדולה יותר עשויה
לעזור לכיסוי, אך אינה מבטיחה לבדה דיוק גבוה יותר.

בחלק ממודעות ארגנטינה היררכיית המיקום במקור אינה אחידה: לעיתים יישוב נמצא
בעמודת `province` ולעיתים `city` מכילה נתיב אזורים מלא. כלי החיזוי מזהיר כאשר
המיקום שהוזן לא הופיע באותה צורה באימון; במקרה כזה הוא נשען יותר על שאר
מאפייני הנכס ולא מציג את המיקום כאילו זוהה בוודאות.

## איך משתמשים בפרויקט?

### 1. פתיחת סביבת העבודה

יש לפתוח PowerShell בתיקיית הפרויקט ולהפעיל:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

אם `.venv` כבר קיימת ותקינה, מספיק להפעיל אותה ולהתקין/לעדכן את הדרישות.

### 2. סדר העבודה הרגיל

1. לעדכן את נתוני המאקרו, אם צריך:

   ```powershell
   python code/fetch_macroeconomic_data.py
   ```

2. לבנות מחדש את קובץ המודל מהנתונים שכבר נאספו, בלי גלישה באינטרנט:

   ```powershell
   python code/scrape_real_estate_training_data.py --rebuild-model-only
   ```

3. לפתוח ולהריץ לפי הסדר:

   - `code/eda_real_estate.ipynb`
   - `code/real_estate_model.ipynb`

4. לקבלת חיזוי אחד דרך הטרמינל:

   ```powershell
   python code/predict_property.py
   ```

   יש להזין את הערכים באנגלית. עבור מדינה משתמשים ב־`AR` או `UY`, ועבור
   סוג הנכס ב־`Apartment` או `House`. התוכנית מסמנת אילו שדות אופציונליים,
   מזהירה אם הוזן מיקום שלא הופיע באימון ומדפיסה מחיר משוער בדולר. בכל הרצה
   היא מאמנת מחדש מה־CSV העדכני, ולכן אין צורך לנהל קובץ מודל נוסף.

5. לבדיקה אוטומטית משורת הפקודה:

   ```powershell
   $env:MPLBACKEND = "Agg"
   python -m jupyter nbconvert --execute --to notebook --inplace `
     --ExecutePreprocessor.timeout=900 `
     code/eda_real_estate.ipynb code/real_estate_model.ipynb
   ```

### 3. איסוף נתונים חדשים

ה־scraper תומך בין היתר ב־`--sites`, ב־`--apartments-only` וב־`--merge-existing`.
מומלץ להתחיל בהרצה קטנה וממוקדת ולאסוף רק מאתרים שמותר לסרוק לפי
`docs/sitelist.md` ו־robots.txt. במצב `--merge-existing` נשמר גם המידע הגולמי
הקיים ומתבצע איחוד לפי כתובת מודעה, במקום לדרוס אותו.

## מה כדאי לעשות בהמשך?

1. לאסוף תצפיות מתוארכות באופן קבוע כדי ליצור סדרת זמן אמיתית.
2. להגדיל את מספר הרשומות מארגנטינה וממקורות שאינם InfoCasas.
3. לבדוק ביצועים בנפרד לפי מדינה ולפי סוג נכס אחרי שיהיו מספיק רשומות בכל קבוצה.
4. לשקול split לפי זמן או לפי קבוצת נכסים/מיקום כאשר יהיו מזהים ותאריכים אמינים,
   כדי לבדוק הכללה בצורה מחמירה יותר מחלוקה אקראית.
